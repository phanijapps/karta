# Svelte 5 + FSD Frontend (frontend/)

Authority: `frontend/AGENTS.md`. Pure SPA: Svelte 5 + TypeScript + Vite +
Tailwind, zero SSR, output to `frontend/dist/`.

## Svelte 5 Runes Only

- Use `$state`, `$derived`, `$effect`, `$props`.
- **Never** Svelte 4 syntax: no `$:` statements, no `export let`.
- The SSE Timeline Tree store must be runes-based so 100+ tokens/sec streams
  and nested sub-agent tool calls render at 60fps with minimal memory.

## FSD Layers and Imports

```
app        → shell layout, routing, theme, platform bootstrap
features   → chat-stream, timeline-tree, wards, config-editor, settings
entities   → session, agent, memory-fact, timeline-event
shared     → generated API client, SSE store, platform adapter, UI primitives
```

- Import direction strictly downward: `app → features → entities → shared`.
- No cross-feature imports; no upward imports.
- New UI work lands in the correct layer — ask which layer owns it before
  writing files.

## API and SSE Rules

- Daemon access ONLY via the generated client in `src/shared/api/`
  (regenerated by `task codegen` from `contracts/openapi.yaml`) and the
  centralized SSE Timeline Tree store. No per-feature `fetch` calls.

## Wails v3 Integration

- `frontend/` must run identically in a browser (`task dev`) and the Wails
  WebView (`task build:desktop`).
- ALL `@wailsio/runtime` usage stays behind `src/shared/platform/`; nothing
  else imports Wails APIs.
- `vite.config.ts`: `server.port = Number(process.env.WAILS_VITE_PORT) || 9245`
  with `strictPort: true`.

## Checklist Before Finishing

- [ ] No `$:` / `export let` anywhere in changed files
- [ ] Imports follow layer direction; no cross-feature imports
- [ ] No direct daemon calls outside the generated client
- [ ] Wails APIs only touched inside `src/shared/platform/`
