# Karta frontend

A local chat workspace. Svelte 5 runes, TypeScript, Vite and Tailwind; no SSR or account required. The Providers settings section is live and manageable (daemon-backed CRUD with OS-keyring credentials); chats remain shell-only until agent integration lands.

## Quick start

Prerequisites: Node.js 22.12+ (or a compatible newer release), pnpm 9.15.9, and [Task](https://taskfile.dev/installation/).

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
cd ..
task dev
```

Open http://127.0.0.1:9245. `WAILS_VITE_PORT=9250 task dev` changes the port. A busy port fails rather than silently selecting another.

```sh
task check:frontend  # svelte-check + static production build
task test:frontend   # local Chromium interaction and axe checks
task verify          # contracts, Go lint/tests/build, frontend checks/tests
```

On Linux, Chromium may need system libraries: `pnpm exec playwright install --with-deps chromium` installs them where authorized. See the root README for Go/tool prerequisites. To serve a production build, run `pnpm build && pnpm preview` from this directory.

## Code organization

Use small responsibility-focused components and colocated feature fixtures, following the useful organizational patterns in Open WebUI without copying its application or SvelteKit stack.

- `src/app/`: bootstrap and composition of navigation, chat, context, and overlays.
- `src/features/chat-stream/`: transcript, model preview, and composer.
- `src/features/settings/`: settings navigation; `Providers.svelte` is the live managed-providers panel (CRUD + keyring), the other sections keep config-shaped fixture drafts here.
- `src/entities/session/`: typed sample sessions and page-lifetime runes state.
- `src/shared/ui/`: reusable overlay behavior, not feature logic.
- `src/shared/styles/`: primitive → semantic tokens and shared base styles.
- `src/shared/api/schema.d.ts`: generated by `task codegen`; never edit by hand.
- `src/shared/api/client.ts`: the only module that talks to the daemon; typed by the generated schema.
- `tests/`: browser behavior, accessibility, and reproducible capture tooling.

Imports flow `app → features → entities → shared`; features never import one another. Use `$state`, `$derived`, `$effect`, and `$props`, not legacy reactivity. Add focused components when responsibility grows; do not split every field into an unnecessary abstraction. Keep docs near their subject and record architecture decisions in `docs/architecture/`.

## Shell behavior

Left navigation collapses to an icon rail on desktop. Below 768px it becomes a drawer; the right panel becomes a drawer below 1280px. The right panel starts closed. New Chat and sample conversation selection work in memory. Enter sends a deterministic mock reply, Shift+Enter inserts a newline, and IME composition does not send.

The header/composer model picker lists models from the daemon's catalog (`GET /api/models`) — refresh it manually in Settings → Providers (Test connection or Refresh models both update it; the daemon never polls providers). Settings includes Providers, MCP, Skills, Logging, and Advanced. Providers is a live, manageable view of the daemon's providers: add, edit (rename, base URL, credential), and delete daemon-managed providers (files under `~/.zbot/config/providers/`, origin-badged "Managed"), while `config.yaml`-declared providers show a `config.yaml` badge and stay read-only (edit the file; restart applies). Test connection asks the daemon to list the provider's models and shows the ids or a typed failure. API keys entered in the form go to the OS keyring once and are never displayed again — only their status; an unavailable keyring fails with typed guidance, and no-credential providers (local ollama) need none. The remaining sections are shell previews: drafts survive section changes but closing the dialog discards them; Reset preview restores fixture values. Path hints are text, not file access.

### Running against the daemon

The dev server proxies `/api` and `/healthz` to the loopback daemon (`http://127.0.0.1:8787`, override with `ZBOTD_URL`). To see live providers:

```sh
cd backend && go run ./cmd/zbotd   # terminal 1: the daemon
cd frontend && task dev            # terminal 2: the SPA
```

Add providers from Settings → Providers (Add provider) — changes apply immediately and persist as files under `~/.zbot/config/providers/`; API keys go to the OS keyring (on headless Linux without a keyring service, credential forms fail with a typed error — env-referenced and no-credential providers work regardless). Hand-authored `config.yaml` entries stay read-only and restart-applied. Without a daemon, Settings → Providers shows an explicit daemon-unreachable state — never fixture data. Playwright tests stub the provider endpoints with route mocks, so `pnpm test` needs no running daemon.

Everything resets on reload, including theme. No browser storage, telemetry, or external assets. Chats, MCP/Skills/Logging/Advanced previews, and agent execution remain shell-only; no SSE integration is present yet.
