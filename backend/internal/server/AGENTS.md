# server

The zbotd HTTP daemon surface: every operation in `contracts/openapi.yaml`,
mounted from generated glue in `internal/server/apigen` (regenerated by
`task codegen`; committed). Imports config + providers + registry +
mcpclient; never imports clients, engine, or UI code.

- `New(store, client, catalog, chat, engine, bus, db, reg, prober,
  version)` builds the server over the provider `Store` and the
  control-plane registry; `Routes()` mounts the contract via
  `apigen.HandlerFromMux` so paths stay in lockstep with the contract.
  Implemented: `GET /healthz`, provider list/models, provider CRUD
  (`POST`, `PATCH`, `DELETE`), the model catalog (`GET /api/models`,
  instant snapshot) and manual refresh
  (`POST /api/providers/{name}/models/refresh`) — the daemon (not the
  client) dials providers; discovery success warms the catalog — plus
  MCP management (`/api/mcps` CRUD + `POST .../test` probe) and skill
  management (`/api/skills` CRUD + detail) over the registry's write
  paths.
- MCP/skill handlers (registry_handlers.go): mutations run through
  `registry.Registry` write paths (serialized with its watcher);
  listings carry bounded per-file `load_errors`; `PATCH` is full-replace
  (PUT semantics). Error mapping (`writeRegistryError`):
  not_found → 404; duplicate_name (name OR occupied target path) → 409;
  invalid_name/invalid_manifest → 400; capacity → 409
  `mcp_limit`/`skill_limit`; io_error/unconfigured → 500. The MCP test
  endpoint probes each declared transport via the injected
  `mcpclient.Prober` and returns typed per-transport results as 200
  bodies (a broken config is expected data, never 5xx). MCP `env` maps
  are file content the user authored and round-trip; no keyring
  interaction.
- MCP import (mcpimport_handlers.go over internal/mcpimport): POST
  /api/mcps/import — the paste arrives as raw text; PARSING and
  classification live in `internal/mcpimport` (order-preserving token
  walk, exact number literals, duplicate-key rejection at every depth
  before any write; classification by wrapper presence: mcpServers
  authoritative, servers alias, single-object, bare map)
  and is separate from per-entry validation; the field-policy table
  maps entries (only command/args/env/url reach manifests; foreign
  keys warn by name, disabled/other-OS entries skip, sse warns);
  outcomes are per-entry in paste order with duplicate-before-capacity
  via registry.CreateMCPFromKey and io_error continue-semantics.
  replaceName is edit-as-JSON: exactly one entry replaces the target's
  transports wholesale (name unchanged), target untouched on any
  reject.
- Skill marketplace handlers (skillhub_handlers.go): daemon-proxied
  skills.sh search (typed index-unreachable), byte-binding repo previews
  (immutable commit + opaque capability + per-file digests; installs
  consume capabilities only and re-verify digests on the pinned commit —
  changed-upstream is typed), and the two-step archive import (multipart
  preview staging via one-shot bearer capabilities with synchronous
  expiry + startup reclamation; commit installs with origin `import`).
  The archive-preview route is the ONE multipart exemption from the
  JSON-mutation rule, protected instead by trusted-Host plus Origin
  enforcement; every other route keeps the JSON rule.
- Guard (guard.go): on the default loopback bind, EVERY request must
  carry a trusted Host — loopback IP, `localhost`, or absent —
  rejecting DNS-rebound hostnames before they reach env-bearing reads
  or the command-spawning probe. Mutations additionally require a JSON
  content type and a loopback/same-host Origin when the browser
  supplies one (hosts compared port-insensitively). An operator may
  expose the daemon (`server.address` wildcard/LAN + SetExposedBind
  from zbotd): Host enforcement is then skipped — an explicit trust
  decision putting an unauthenticated API on the network — while the
  Origin rule keeps comparing hosts.
- OpenAI-compatible channel (openai_handlers.go, intent-context-packet
  change): `GET /v1/models` + `POST /v1/chat/completions` map OpenAI
  client conversations (OpenWebUI first) onto sessions — model selects
  the type (karta-research/karta-chat), first-user-message hash is the
  stable id, reply = final assistant row, typed failures carry the
  OpenAI error shape (busy → 409). Optional bearer (`SetV1Token`,
  server.api_token); unset keeps loopback.
- Session state (`GetSessionState`): the session row + LATEST
  intent_analysis (read from persisted events) — the UI's analysis
  card and context panel render from this, never transcript parsing.
- Session CRUD (add-chat-modes): `GET /api/sessions` lists the roster
  (type + ward binding, recency-ordered — the sidebar's grouping data;
  cursor = offset), `POST /api/sessions` creates research shells, and
  `GET /api/sessions/{id}` reads one. Chat sends are SESSION-scoped
  (`session_id` on send/sync/clear; the SERVICE routes by type — no
  mode branch in the handlers); unknown ids fail typed 404. Remaining
  goal/SSE operations ride the generated `Unimplemented` stubs (501)
  until their owning change lands.
- Error mapping (`writeMutationError`, providers_handlers.go):
  `ErrUnknownProvider` → 404; `ErrNameExists`/`ErrCapacity`/
  `ErrOriginProtected` → 409 (`duplicate_name`/`provider_limit`/
  `origin_protected`); `ErrKeyringUnavailable` → 503; validation → 400.
  Discovery failures: typed `*providers.Failure` → 502 with `reason`;
  an unresolvable keyring credential → 502 `credential_unavailable`
  (never a silent unauthenticated request).
- Credential bodies cross the API exactly once: the one-shot `key` in
  create/edit requests. Responses carry names, kinds, and statuses only
  (`providerView`); values never appear.
- No eventbus emission here: provider CRUD is not an agent step, tool
  call, hook decision, or compaction event (design D6/D8 of the provider
  changes records the reasoning).
- Tests run the daemon over `httptest` with a temp home, in-process fake
  providers, an in-memory SecretStore, and a fake `Prober`; zero live
  network in `go test`.

- Streaming + leave (harden-mcp-and-ux): `stream: true` on
  /v1/chat/completions → bare-data `chat.completion.chunk` frames;
  the stream's conclusion (answer, finish_reason, `[DONE]`) rides
  `streamWriter.finishAll` — an ORDERED, non-droppable terminal path
  (volatile `send` may drop under a slow client; the conclusion never
  is). Busy research answers 409 JSON BEFORE any header. Leave-ward:
  `POST /api/sessions/{id}/leave-ward` (204/404/409 default) clears
  the binding and calls the wired `wardDropper` (the engine's host
  reset).
- Intent analysis (intent_handlers.go, sse_events.go): the Settings
  card's `GET/PUT /api/intent-analysis` (the daemon-managed
  `intent-analysis.json` + the read-only derivation through
  `providers.ResolveWindow`) and `POST /api/intent-analysis/test` (the
  `IntentTester` seam = the wrapped engine's probe). Durable replay
  (`dbSessionEvents`) translates legacy `intent_analysis` rows to the
  terminal `analysis_*` kind their status names; session state reads
  the latest terminal analysis (legacy rows included).
