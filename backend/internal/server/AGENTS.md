# server

The zbotd HTTP daemon surface: every operation in `contracts/openapi.yaml`,
mounted from generated glue in `internal/server/apigen` (regenerated by
`task codegen`; committed). Imports config + providers; never imports
clients, engine, or UI code.

- `New(store, client, version)` builds the server over the provider
  `Store`; `Routes()` mounts the contract via `apigen.HandlerFromMux` so
  paths stay in lockstep with the contract. Implemented: `GET /healthz`,
  provider list/models, provider CRUD (`POST`, `PATCH`, `DELETE`), the
  model catalog (`GET /api/models`, instant snapshot) and manual refresh
  (`POST /api/providers/{name}/models/refresh`) — the daemon (not the
  client) dials providers; discovery success warms the catalog.
- Goal/session/SSE operations ride the generated `Unimplemented` stubs
  (501) until their owning change lands.
- Error mapping (`writeMutationError`, providers_handlers.go):
  `ErrUnknownProvider` → 404; `ErrNameExists`/`ErrCapacity`/
  `ErrOriginProtected` → 409 (`duplicate_name`/`provider_limit`/
  `origin_protected`); `ErrKeyringUnavailable` → 503; validation → 400.
  Discovery failures: typed `*providers.Failure` → 502 with `reason`;
  an unresolvable keyring credential → 502 `credential_unavailable`
  (never a silent unauthenticated request).
- Credential bodies cross the API exactly once: the one-shot `key` in
  create/edit requests. Responses carry names, kinds, and statuses only
  (`providerView`); values never appear.
- No eventbus emission here: provider CRUD is not an agent step, tool
  call, hook decision, or compaction event (design D6/D8 of the provider
  changes records the reasoning).
- Tests run the daemon over `httptest` with a temp home, in-process fake
  providers, and an in-memory SecretStore; zero live network in `go test`.
